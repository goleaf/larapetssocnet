# PetSocial  

PetSocial is a Laravel social network for pet profiles, feeds, groups, adoption browsing, marketplace listings, messaging, notifications, health logs, moderation, and shared media.

Application browsing pages are private by default. Guests can access authentication and system pages such as login, registration, password reset, email verification, and the banned notice; signed-in users must have an active, non-banned, non-suspended, non-deactivated account and verify their email before accessing Explore, search, posts, pets, adoption, marketplace, events, hashtags, tips, groups, feeds, messages, and settings. Public username profile URLs are the controlled exception: they resolve only active profiles and render viewer-aware public or locked states without private sections, private counts, contact details, email search matches, or unavailable accounts. Public profile portfolio URLs at `/@username/portfolio` are also guest-accessible, but only show owner-curated posts that are published, public, and guest-visible. Pending-deletion and deactivated accounts are restricted to password-confirmed recovery screens. 

## Stack
 
- PHP 8.4
- Laravel 13
- SQLite by default for local and shared-hosting deployments
- Pest 4 and PHPUnit 12
- Larastan/PHPStan, Rector, and Pint for PHP quality checks
- Tailwind CSS 4, Sass, Vite 8, Alpine 3, and daisyUI 5

## Local Setup

```bash
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed
npm install
npm run build
```

This project is structured for shared hosting where the repository root is the web-served directory. The Laravel front controller, `.htaccess`, `build/`, `images/`, `favicon.ico`, and `robots.txt` live at the root; private Laravel folders are blocked by `.htaccess`. For active frontend work, run `npm run dev`; for production-like asset checks, run `npm run build`, which writes Vite assets to `build/`.

Profile location autocomplete is configured through `GEOCODING_ENDPOINT`, with optional `GEOCODING_KEY`, `GEOCODING_TIMEOUT`, and `GEOCODING_LIMIT` values. When no endpoint is configured, the profile edit modal simply skips server-side suggestions.

Profile Wrapped annual summaries are generated by `php artisan profiles:wrapped-generate`, scheduled daily during January 1-7. The command stores owner/year analytics in `profile_wrapped_summaries` and generates public PNG share cards under the configured public disk.

Scheduled posts are published by `php artisan posts:publish-scheduled`, scheduled every minute. The command uses a database cache lock, selects due posts through the indexed `posts.status` / `posts.scheduled_publish_at` lookup, and publishes each due post through `ScheduledPostPublisherService`; feed fan-out and mention notifications run only after the post is actually published.

Post composer link previews are fetched server-side by `PostLinkPreviewService`. Pasted URLs trigger an Open Graph fetch with a 5-second Guzzle timeout and redirect tracking; the composer polls a short-lived cache key for preview metadata, while created posts without preloaded metadata are saved immediately and updated by the same service after creation.

Post composer drafts autosave in the background every 10 seconds after content changes. The `post_drafts` table stores one serialized composer state per user behind a unique `user_id` index; opening the composer shows a resume/discard banner instead of restoring content automatically, and successful submission or confirmed cancellation clears the saved draft.

Post composer entry points reuse the same Livewire `posts.composer` component from the feed inline composer, the owner profile Posts tab modal, and the authenticated mobile floating action button. The contenteditable editor highlights hashtags and mentions locally, while active mention text also triggers a debounced server-backed username suggestion list capped at five accounts.

Post composer submission disables the composer while the action runs, routes duplicate detections through a confirmation modal, preserves entered content on validation failures, dispatches success toasts for published and scheduled posts, and emits a `post-created` browser event with enough metadata for feed surfaces to prepend newly published posts optimistically.

Post editing opens the same Livewire composer in modal edit mode from owner post-card menus. Editing is limited to 24 hours from creation in both the UI and `UpdatePostAction`; successful edits re-sync hashtags, mentions, pet tags, mood, location, visibility, and link previews, dispatch `post-updated`, and show the shared post card `Edited` timestamp label.

Post deletion opens the shared Livewire confirmation modal, dispatches the optimistic `post-delete-requested` event, soft-deletes the post immediately inside the confirming request, and then runs `PostDeletionCascadeService` for pet counters, hashtag counters, precomputed feed items, saved-post placeholders, and media cleanup.

Post reactions use the polymorphic `reactions` table with one active reaction per user per post. Shared post cards render an Alpine emoji picker for the configured Paw, Love, Haha, Wow, Sad, and Angry reactions while preserving the legacy like endpoint as a default Paw toggle for older surfaces. `ReactionService` performs atomic counter-cache updates for total and per-type post counters, returns the current viewer reaction and breakdown counts for optimistic UI reconciliation, and keeps feed/list queries from issuing per-card reaction lookups through the `current_user_reaction_type` subselect. Reaction counts open a paginated Livewire list modal, and comments use the simplified Paw/Love counter set.

Inline feed comments mount through the nested Livewire `posts.comments-thread` component when a post card's comments panel opens. Feed panels show the three most recent top-level comments with two recent replies per thread, while post detail pages mount the same component in full-page mode with Top/Newest/Oldest sorting. The shared component uses `CommentService` for three-level visual threading, mention suggestions, emoji insertion, reaction summaries, soft-delete tombstones, pinning, reports, blocking, and visible polling with a lightweight thread activity fingerprint, then dispatches parent post-card refresh events so comment counters stay synchronized.

Pet profiles use the canonical authenticated `/pets/@{pet:slug}` route through the full-page Livewire `pages.pets.show` wrapper, which keeps reactive tab state while reusing the existing show controller/view data preparation. Pet birthday notifications are generated by `php artisan pets:send-birthday-notifications`, scheduled daily at `config('pets.birthday.notification_time')`, and use the indexed `pets.birthday_month_day` lookup maintained from pet birth dates. The command processes each matching pet through `PetBirthdayService`, creates the system birthday post through the normal post pipeline, and notifies eligible pet followers and co-owners. Pet health reminders are generated by `php artisan pets:send-health-reminders`, scheduled daily at `config('pets.health_reminders.notification_time')`, and notify the primary owner plus accepted co-owners before advancing each reminder's next due date. Pet profile sharing uses server-generated SVG QR codes and does not require an external QR package.

Authentication supports full-page Livewire registration, login, forgot-password, and reset-password flows; a dedicated `AuthenticateUserAction` for email-or-username credential resolution; verified-email gating through the Bootstrap-defined `auth.verified` middleware group; queued branded email verification and password reset mailables; magic login links; TOTP two-factor authentication with recovery codes; password reset session/remember-token invalidation; device-session review; and Google/Facebook OAuth handoff. Login uses generic credential-failure responses, Laravel `RateLimiter` lockouts after 5 failed attempts for 60 seconds with a Livewire/Alpine countdown, 30-day remember-me sessions, feed redirects after successful password login, explicit remember-token cleanup on logout, an inline magic-link panel that queues a one-time login Mailable with a raw 64-character emailed token and SHA-256 database lookup hash, and an inline password-reset request panel that shares the same action as `/forgot-password`. Account security reads database sessions by user ID, parses browser/device/OS details locally, labels the current session, supports individual other-session logout, and requires the current password before logging out all other devices and clearing persistent remember tokens. Password reset links use Laravel's broker storage plus a SHA-256 lookup hash inside a signed URL, redirect successful resets to the login page after invalidating all existing sessions, and send a password-change security alert with a signed single-use emergency lock link for administrator review. Successful logins run country-anomaly detection through `LoginAnomalyDetectionService` using recent auth audit history and local IP geolocation; security alert links are signed and single-use, either dismissing the alert or invalidating all sessions, clearing remember tokens, and creating a high-priority moderation report. Registration handles hyphenated usernames, real-time username/email validation, DNS email validation, DOB selects, terms/privacy modals, honeypot false success, and Alpine password-strength feedback backed by SHA-256 common-password hashes. Expired but correctly signed email verification links send the user to the Livewire verification page with a resend action and success toast support. Logout forms are guarded by an Alpine dirty-state check when unsaved post drafts exist. The auth schema is consolidated into one focused migration, uses `users.last_active_at` for online presence, stores OAuth links in `social_accounts.provider_user_id` with encrypted `provider_token`, stores one-time link lookups in `magic_link_tokens.token_hash`, and stores login anomaly alerts in `login_security_alerts`. Configure OAuth with `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `FACEBOOK_CLIENT_ID`, and `FACEBOOK_CLIENT_SECRET`; provider URLs can be overridden through the matching `*_REDIRECT_URL`, `*_TOKEN_URL`, and `*_USER_URL` env values.

Local authentication testing expects `SESSION_DRIVER=database`, `QUEUE_CONNECTION=database`, and a local Mailpit SMTP interceptor at `127.0.0.1:2525` with the Mailpit UI at `http://127.0.0.1:8025`. Database sessions are required for device-session review and invalidation; the default queue worker must process the `database:default` queue for verification, reset, magic-link, and security notification emails. Production shared-hosting deploys default to `MAIL_MAILER=phpmail`, which uses PHP `mail()` directly and avoids Symfony's `proc_open()`-based sendmail transport on hosts that disable shell execution. IP geolocation for auth surfaces is file-backed through `GEOIP_DATABASE_PATH`, defaulting to `database/geoip/ip-ranges.json`, and must not call a remote API during session rendering.

After email verification, incomplete users enter the full-page Livewire onboarding flow at `/onboarding`. Onboarding collects optional profile details, can use the OAuth provider avatar suggestion, creates a simplified first pet through the existing pet action, writes follow relationships immediately, records completion on the user row, and shows a dismissible 24-hour welcome banner plus a one-time skipped-pet reminder on the feed.

Post media finalization uses Spatie Media Library through `PostMediaProcessingService`. Livewire temporary uploads create processing placeholder rows, then finalized post media is stored on the public media disk under `posts/YYYY/MM/DD/{media_id}/` with derivative folders for conversions and responsive images.

The main `/feed` surface is a full-page Livewire `pages.feed.index` component. The center `feed.stream` component loads first, while `feed.left-sidebar` and `feed.right-sidebar` hydrate lazily as nested sidebar components. The stream reads precomputed delivery rows from `feed_items`, with compatibility fallback branches for the viewer's own posts, accepted followed users, and followed pets through both legacy `posts.pet_id` and normalized `pet_post` tags, then applies outer Eloquent visibility, block, mute, ordering, and cursor pagination rules so duplicate source matches render once and stale feed rows cannot leak content. It keeps `source=people|pets`, `type=text|photo|video`, and `rank=best` filters in the URL; supports Latest and lightweight Best ranking backed by each user's `feed_ranking_preference`; appends 15-post cursor pages through `wire:intersect`; stores the last loaded post ID in the session for same-session read-position restore; excludes muted users and pets without removing follow rows; and polls for newer posts only while the browser tab is visible, fetching only a count and newest post ID until the user taps the indicator. Feed fan-out is handled by `FeedFanOutService`, which writes precomputed delivery rows in 500-row chunks keyed by recipient/source uniqueness. Feed post cards render as reusable Livewire `posts.card` islands around the shared `x-post-card`, trending hashtags are cached through tag-aware cache with a fallback for stores without tags, and feed images use native lazy loading with optional blurhash placeholder metadata.

Local authentication testing expects `SESSION_DRIVER=database`, `QUEUE_CONNECTION=database`, and a local Mailpit SMTP interceptor at `127.0.0.1:2525` with the Mailpit UI at `http://127.0.0.1:8025`. Database sessions are required for device-session review and invalidation; the default queue worker must process the `database:default` queue for verification, reset, magic-link, and security notification emails. Production shared-hosting deploys default to `MAIL_MAILER=phpmail`, which uses PHP `mail()` directly and avoids Symfony's `proc_open()`-based sendmail transport on hosts that disable shell execution. IP geolocation for auth surfaces is file-backed through `GEOIP_DATABASE_PATH`, defaulting to `database/geoip/ip-ranges.json`, and must not call a remote API during session rendering.

Livewire 4 and Alpine are bundled once through `resources/js/app.js` using Livewire's ESM entrypoint. Shared layouts render Livewire styles and script config through Livewire frontend asset helpers, not raw `@livewireStyles` / `@livewireScripts` directives.

## Local Debugging

Laravel Debugbar is installed as a dev dependency and configured through `config/debugbar.php`. Keep committed env defaults disabled; for local Herd debugging use `APP_DEBUG=true` and `DEBUGBAR_ENABLED=true` in `.env`. Do not enable Debugbar or open Debugbar storage in production.

## Design System

The app uses the Open Design Warm Editorial system as its single visual standard. Source tokens live in `resources/scss/abstracts/_tokens.scss` and are exposed as shared CSS custom properties for the warm paper canvas, serif-led headings, terracotta actions, forest/meta accents, underline inputs, flat surfaces, and hover-only elevation.

Use the shared primitives from `resources/scss` and Blade: `x-ui.page-stack`, `shell-card` / `ui-card`, `ui-panel`, `ui-list-item`, `ui-token`, `ui-media-frame`, `ui-card-interactive`, `ui-container`, `ui-section`, and the shared `btn-*` variants. Keep repeated cards, metric tiles, list rows, media wrappers, links, controls, and chips on these primitives instead of adding page-specific `bg-white`, `rounded-xl`, `shadow-sm`, gradients, glass effects, dark/light theme toggles, runtime visual style switchers, `data-theme` controls, or one-off border palettes. Profile page personalization is limited to the five accessible, config-backed `ProfileTheme` choices applied as CSS custom properties on the profile root.

The application shell uses a scroll-contained desktop left rail, in-flow mobile quick navigation, and a fluid 1440px portal container with responsive gutters. Keep primary page content full-width inside the main portal column unless a narrow reading measure is intentional. Do not add fixed mobile navigation that can cover forms, feed cards, or primary action rows.

## Deployment

The repository includes an FTP deployment workflow for shared hosting:

- `.github/workflows/deploy-ftp.yml`
- `scripts/prepare-ftp-deploy.sh`
- `scripts/deploy-ftp-archive.sh`

Required GitHub secrets are `APP_KEY`, `FTP_HOST`, `FTP_USERNAME`, and `FTP_PASSWORD`. Runtime deployment values such as `APP_URL`, `REMOTE_BASE`, `FTP_SERVER_DIR`, FTP protocol settings, and mail settings can be configured as GitHub Actions variables. Shared-hosting deploys default `MAIL_MAILER` to `phpmail`, a PHP `mail()` transport that does not shell out through `proc_open`; set `MAIL_MAILER=smtp` and provide the `MAIL_PASSWORD` secret only when the production SMTP credentials are known-good.

The deployment package keeps Laravel application code under `laravel/`, publishes the shared-hosting entry point and root assets at the FTP target, uploads one ZIP archive over FTP, and triggers a temporary token-protected PHP deployer over HTTPS. The deployer removes stale remote application files before extracting the archive, while normal deploys preserve remote SQLite/runtime data unless the manual `include_sqlite` workflow input is enabled for first installation.

The production smoke workflow can be dispatched manually after a deploy to verify `/login`, invalid-login handling, and remote Laravel log access. Use the optional log-fetch input when diagnosing registration, verification, reset, magic-link, or mail transport failures on the subdomain; stale remote stack traces should be compared by timestamp before treating them as new failures.
